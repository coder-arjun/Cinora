# Cinora

A social movie-and-series review platform, built on ASP.NET Core 10 with Clean Architecture.

## Features

Everything runs on **free, local, self-hosted** components — no Docker, no cloud services, no paid packages.

- **Discovery** — trending / popular / top-rated rails, search, and rich title details, sourced from the free TMDB API and cached locally.
- **Reviews & social** — reviews with ratings out of 10, likes, comments, friends, and a friends activity feed.
- **Watchlists & profiles** — add-to-watchlist from every title surface with status tracking, editable profiles with avatar uploads, and privacy-shaped public profiles.
- **AI recommendations** — a personalized *For You* rail and `/recommendations` page, generated by a local LLM via Ollama behind a swappable `IRecommendationEngine` port (no paid OpenAI).
- **Installable PWA + offline** — installs as a Progressive Web App; core public browsing works offline with a designed fallback for uncached routes.
- **Web Push + notification preferences** — out-of-app notifications via self-generated VAPID keys (no paid gateway), with per-type opt-out in settings; push is additive and degrades to off when unconfigured.
- **Realtime** — in-app notification toasts and badges over self-hosted SignalR.

## Local development

Everything below is **free and local** — no Docker, no cloud services, no paid packages.

### Prerequisites

| Tool | Version | Notes |
|------|---------|-------|
| .NET SDK | 10.0.x | See `global.json` (pinned to 10.0.301). |
| Node.js + npm | Node 20+ (Node 22 recommended) | Drives the Tailwind v4 + TypeScript asset build. |
| SQL Server LocalDB | `(localdb)\MSSQLLocalDB` | Ships free with the SQL Server Express / Visual Studio installers. |
| `dotnet-ef` global tool | 10.0.x | `dotnet tool install --global dotnet-ef` (only needed to apply migrations). |

Windows PowerShell 7+ is assumed for the `scripts/` helpers.

### First-run setup

From the repository root:

```powershell
# 1. Restore .NET dependencies
dotnet restore

# 2. Restore front-end dependencies (Tailwind, esbuild, Alpine, HTMX)
npm ci --prefix src/Cinora.Web

# 3. Create/upgrade the local database (idempotent — safe to re-run)
scripts/db-update.ps1

# 4. Run the app with hot reload (C#/Razor via `dotnet watch`, CSS/TS via `npm run watch`)
scripts/dev.ps1
```

`scripts/dev.ps1` prints the local URLs. By default (the `https` launch profile):

- App: <https://localhost:7149> and <http://localhost:5148>
- Health check: <http://localhost:5148/health> (anonymous; `200 Healthy` when the database is reachable, `503 Unhealthy` otherwise)

The front-end watcher runs as a background job named `cinora-frontend-watch` and is stopped automatically when `dotnet watch` exits (Ctrl+C). To stop it manually: `Stop-Job -Name cinora-frontend-watch; Remove-Job -Name cinora-frontend-watch`.

### Optional secrets (user-secrets — free)

Email/password sign-in and the app itself boot **without** any of these. Set them only to enable the corresponding feature. Secrets never live in `appsettings.json`.

Google sign-in (create a free OAuth client at <https://console.cloud.google.com/>):

```powershell
dotnet user-secrets set "GoogleAuth:ClientId"     "<your-client-id>"     --project src/Cinora.Web
dotnet user-secrets set "GoogleAuth:ClientSecret" "<your-client-secret>" --project src/Cinora.Web
```

TMDB metadata (create a free API key at <https://www.themoviedb.org/settings/api>):

```powershell
dotnet user-secrets set "Tmdb:ApiKey" "<your-tmdb-api-key>" --project src/Cinora.Web
```

Web Push (VAPID keys) and the file-URL signing key are optional too and are configured at deploy time — see the [deployment runbook](docs/deployment/runbook.md) §3. Web Push is additive: unconfigured, it simply stays off and in-app notifications still work.

### Build and test

```powershell
dotnet build Cinora.sln -c Release
dotnet test  Cinora.sln -c Release
```

Integration tests run against a dedicated LocalDB database (`CinoraTest`), which they create and migrate automatically; they never touch your `CinoraDev` data.

## Deployment

Cinora deploys to a **free / local / self-hosted** stack — no Docker, no cloud subscription, no paid tier. The full, human-runnable procedure (database targets, per-environment secrets, the idempotent migration flow with its pre-apply checks, publish + PWA-artifact verification, the Data-Protection key ring, and the manual verification checklist) lives in the **[deployment runbook](docs/deployment/runbook.md)**. Deployment is plans-only: a person runs it — no automation applies it.

Two points worth repeating here:

- Production **must** set `ASPNETCORE_ENVIRONMENT=Production` **exactly**. A typo such as `Prod` is treated as an unknown environment and would leave the Development/Testing-only diagnostics endpoints exposed. On an unrecognized environment name the app logs a startup Warning (non-fatal) so the mistake is visible in the logs.
- Database migrations are applied from a **reviewed idempotent SQL script** — the app never auto-migrates on startup:

  ```powershell
  dotnet ef migrations script --idempotent `
    --project src/Cinora.Infrastructure --startup-project src/Cinora.Web `
    --output migrate.sql
  ```
